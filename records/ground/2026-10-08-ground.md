The same shapes crash `check_defensibility` (REM-2). Re-verified by the orchestrator at `engine/src/analysis.rs:452-462` and `:500-520`.
2. **CI has not carried a signal for months.** The WASM gate has been red on every run since it was added (TRUST-1), the threaded, reproducibility and browser byte-parity gates are dark (TRUST-3), cargo-audit cannot compile on the pinned toolchain (TRUST-5), main is unprotected (TRUST-6), and nothing ties the WASM shipped into Meridian to committed source (TRUST-7). Likely cause of the hash split: `rust-src` installed locally, not in CI (TRUST-2, unproven).
3. **Some numbers read as findings are model artefacts.** Per-category "unexplained" drivers depend on the omitted base category and are presented as findings (MEAN-1); a dataset with no gender effect but non-overlapping education is reported as a significant unexplained gap (CMP-1, reproduced with the CLI); weighted quantiles are wrong for fractional weights (QRI-1); the quantile "total gap" is a mean-RIF difference (QRI-2); the default Pooled scheme is the one no oracle checks (BND-3, TRUST-8).
4. **The remedy overstates what it does.** "Optimisation" is sort-and-cap and ignores `target_gap` (REM-7); `adjust_both_groups` credits reference-group raises to the target gap (REM-3); reductions can read over 100% (REM-8); the remedy tests cannot fail on the property they name (TRUST-9).
5. **Strong and verified:** two-fold/three-fold arithmetic and GroupB scheme pinned to R and statsmodels at 1e-6; bootstrap SE replayed against R; weighted RIF; percentile CI refuses below 41 reps; stratified, seeded, bit-reproducible bootstrap; library-only estimators cannot reach a Meridian remedy amount; clean-data remedies land on fair wage to the cent and verify independently. Full strengths per lane at the end.

- **BND-2**: Core claim holds. Two refinements: (1) the index shift is not guaranteed. It occurs only when third-value rows precede or interleave with the compared group's rows in file order. If they all come last, the extra target_indices go unused, but the summary mismatch and the silent exclusion remain either way. (2) The 0017 row-key gate does trip in this case (y_b.len() != target_indices.len()). This comes from code reading, and the test at oaxaca_blinder/tests/integration_test.rs:97 confirms the builder-level exclusion.
- **BND-2**: With 3 or more distinct values in the group column, OaxacaBuilder::split_groups compares the reference against only the first sorted non-reference value. Rows with any other value are silently dropped from both design matrices. The engine summary (run_decomposition_on_df) and the optimizer (optimize_inner) treat every non-reference row as the second group. As a result group_b_count and group_b_mean include the dropped rows while total_gap does not, and the optimizer's target_indices is longer than the matrix rows. For positional output the shift starts at the first dropped row. Any later target row gets another employee's current_wage (wage_array.get(orig_idx)) and its Adjustment.index points at the wrong employee. If the dropped rows all sit after the kept ones in the file there is no shift. The persistent row_key is not corrupted, because the 0017 P4 alignment gate withholds keys whenever the group lengths differ, though it prints only to stderr. No guard in the engine, MCP or app pre-flight stops this (it only requires >=2 distinct values). The end-to-end optimize effect is read from code, not executed.
- **QRI-2**: decompose_quantile's total_gap is mean(RIF_A) - mean(RIF_B) (builder.rs:853-861 on the RIF-replaced outcome from builder.rs:941-943; engine reads it at engine/src/analysis.rs:209) and Meridian labels it "Total Raw Gap / Écart brut total" with the mean-gap tooltip (GapAnalysisResults.vue:76-79, en.json:1443/3860). It equals the quantile gap only when F_n(q_tau) = tau in both groups, which fails on tied/gridded pay data. This is not hypothetical: the project's own golden fixture (employers_trust_fixture.csv) has only 39 distinct salary values in 10,000 rows, and on it the type-7 p10 and p90 gaps are exactly 0.0 while the shipped/golden figure is +0.0121 (p10) and +0.0011 (p90) log points, and at p50 the shipped +0.0210 is half the true +0.0426. ddecompose's Observed_difference is the same mean-RIF quantity, so the golden test cannot see it (and does not assert total_gap at all). When one group's q_tau sits on a grid step with F_n(q)=1, that group's RIF is constant and its slopes are exactly 0; the split then becomes exactly 100% unexplained only when that group is the reference-coefficient group (GroupA/GroupB; Meridian sends GroupA in 'standard' mode, analysisConfig.store.js:105), and near-total (explained 0.044 of 0.648 in the simulated grid, true quantile gap 0) under the Pooled reference Meridian sends otherwise. No tau, per-group n (beyond 2, rif.rs:111-127) or tie-share guard exists on any surface; tau outside [0,1] is silently clamped (rif.rs:57).
- **QRI-2**: decompose_quantile reports total_gap as the difference in group means of the sample RIF (builder.rs:853-861 run on the RIF-replaced outcome from rif_replace_outcome, builder.rs:941-943; engine reads it at analysis.rs:209 and Meridian shows it in the "Écart brut total" card, GapAnalysisResults.vue:79). Mean sample RIF = q_tau + (tau - F_n(q_tau))/f_hat(q_tau), so the reported total equals the quantile gap only when F_n(q_tau) = tau in both groups. On tied pay grids the offset is large enough to flip the sign: on a 30-row 4-step grid vs a 30-row continuous group, the true p90 gap is +0.994 $/h and the true median gap +0.500 $/h, while the shipped CLI reports Total Gap -0.2516 (p90) and -0.1168 (p50). When a group's q_tau sits on its top step, F_n(q_tau) = 1 and that group's RIF is one constant, so its slope coefficients are zero; the resulting explained/unexplained split is meaningless. "100% unexplained by construction" holds only when the reference coefficients come from the degenerate group (--ref-coeffs group-a: explained -0.0000, unexplained = total); under the engine's default Pooled and the CLI's default group-b the split is nonzero but still built from a constant outcome. The ddecompose oracle uses the same mean-RIF definition (its observed_difference = composition + structure = 0.0121 at p10 and 0.0011 at p90 on the golden fixture, where the type-7 quantile gap is exactly 0.0 because both groups sit on the same grid step), so the golden test cannot detect this. No surface validates tau, group size beyond n>=2, or tie fraction; rif.rs clamps tau only inside weighted_quantile (rif.rs:57) and uses the raw value in the RIF numerator (rif.rs:201).
- **EST-1**: CLI Heckman correction cannot produce a valid selection-corrected decomposition under either available input encoding. With null-encoded unobserved outcomes (the encoding the repo's own test and verification script use, and the only one a user would infer from the README), OaxacaBuilder::run() drops those rows before the estimator runs, so the probit is fit on an all-ones selection vector with no guard; the result is labelled Heckman but is not a Heckman estimate. The manifestation is dataset-dependent, not uniformly a near-zero IMR: when selection differs by group the degenerate IMR column produces exploded, offsetting explained/unexplained components (observed: -1652.78 / +1652.35 on a 4000-row synthetic), which looks wrong rather than right; the near-zero IMR only appears when the selection term is genuinely ~0 (random group assignment, as in heckman_test.rs). With non-null placeholder outcomes for unobserved rows, the probit is fit correctly but total_gap and n_a/n_b are computed over the placeholder rows, so the headline gap disagrees with the components (observed: Total Gap +0.2017 vs components summing to -0.433). Reachable from the CLI only; not from WASM or MCP.
- **EST-1**: As stated, with one addition: the no-op is also reachable through the Python bindings (oaxaca_blinder/src/python.rs exposes selection_outcome/selection_predictors and verification/verify_heckman.py uses that path with NaN-encoded wages), so the affected surfaces are CLI and Python; engine (WASM) and meridian-mcp contain no Heckman wiring and are unaffected.
- **REM-2**: Claim holds as stated. Two precisions. (1) The panic needs the dropped row to be in the non-reference group, or a third group present, because the total_need loop walks every non-reference row. A blank cell in a reference-group row alone shifts only x_a indices, which are touched only if an adjustment targets a reference row. (2) The failure is loud (a trap), not a silently wrong number. The wrong-number variant of the same null-drop misalignment is the already documented one in optimize. High is defensible because blank cells and a third gender category are ordinary HR data shapes and the front-end pre-flight does not catch either.

## Strengths by lane

### NUM — Mean decomposition methodology
- Two-fold and three-fold arithmetic is exactly Jann (2008) eq. 3-7: explained = (x̄_A−x̄_B)'β*, unexplained = x̄_A'(β_A−β*) + x̄_B'(β*−β_B), three-fold E/C/CE from group B's viewpoint (decomposition.rs:63-65, 79-83, 102, 113), and the GroupB scheme is pinned to an independent R lm() oracle at 1e-6 including every per-variable component and the three-fold aggregate (trust_golden_r_test.rs; passes: 1 passed, 2026-10-08).
- Weighting is applied consistently on the OLS mean path: Gram matrix on sqrt(w)-scaled rows (ols.rs:68-81), weighted predictor means (estimation.rs:56-68), weighted outcome means for the gap (builder.rs:853-861), Cotton weights from Σw (builder.rs:769-786), and since 0097 the RIF transform too; so x̄'β = ȳ holds under weights and adding-up is exact.
- Adding-up identities are property-tested over 256 random designs for two-fold, three-fold and detailed-vs-aggregate (decomposition_properties_test.rs:56-123; 6 passed), plus label-swap antisymmetry and scale equivariance.
- The Yun (2005)/Gardeazabal-Ugidos normalisation itself is implemented correctly for the two-fold (centring, intercept shift, base category added back at builder.rs:811-851) and is available at the library level; only its three-fold hook (MEAN-3) and its absence from the shipped surfaces (MEAN-1) are at issue.
- A categorical level confined to one group is refused before estimation with the column, level and group named (builder.rs:176-216), including the zero-weight case, instead of surfacing as a Cholesky failure.
- The bootstrap is stratified by group, re-estimates the pooled model inside every replicate (so pooled-scheme SEs carry the β* uncertainty Jann's delta method accounts for), uses fixed per-rep seeds, and the percentile interval refuses below 41 draws rather than returning the sample range.
### INF — Quantile, RIF and inference
- Bootstrap SE is cross-checked against R on identical committed resample indices at rel 1e-3 (oaxaca_blinder/tests/bootstrap_se_golden_test.rs:1-25); the per-predictor RIF detail is checked against R ddecompose with a key-set guard and an honest tau-dependent tolerance (tests/quantile_detail_golden_test.rs:1-50); quantile regression is checked against quantreg on a tau-varying location-scale design (tests/qr_location_scale_test.rs:1-20).
- RIF is recomputed inside every bootstrap replicate per group (builder.rs:975-977), which is the correct design; the legacy fixed-RIF form is documented as understating CIs (builder.rs:892-896).
- Bootstrap is seeded, stratified by group, resamples by owned index vectors, and records requested/succeeded/discarded in RunMetadata (rng.rs:54-58, builder.rs:1141-1146, rng.rs:103-123); the Meridian results card shows the discarded count (GapAnalysisResults.vue:170-174, 432).
